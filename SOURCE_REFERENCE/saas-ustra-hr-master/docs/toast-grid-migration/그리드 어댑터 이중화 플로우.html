Toast Grid migration

그리드 어댑터 이중화 플로우

페이지 요청마다 URL과 YAML 설정을 확인해 Toast Grid 또는 RealGrid 중 하나만 로드하고, 화면 코드는 동일한 UstraRealGrid API를 사용합니다.

1. 엔진 선택 우선순위

1

URL 파라미터

?gridEngine=toast
?gridEngine=realgrid

현재 요청 한 건에만 적용합니다.

2

YAML 설정

ustra.grid.engine: toast

URL이 없을 때 전체 기본 엔진입니다.

3

기본값

realgrid

URL과 YAML이 모두 없으면 RealGrid입니다.

2. 페이지 접근부터 그리드 생성까지

브라우저에서 메뉴 페이지 요청/메뉴경로/view
↓
Thymeleaf 레이아웃 적용footerlayout · configlayout · mainconfiglayout
↓
gridEngine 결정URL 파라미터 → YAML → 기본값 realgrid
↓

Toast 경로

  1. TUI Grid 의존성 로드
  2. ustra.toast.grid.js 로 Toast 래퍼 로드
  3. ustra.grid.compat.js 로 호환 API 노출
  4. 내부 Toast Grid 생성

RealGrid 경로

  1. ustra.realgrid.js 로 기존 래퍼 로드
  2. RealGrid components·라이선스 로드
  3. 기존 RealGrid GridView 생성
  4. 호환 어댑터는 로드하지 않음
↓
뷰의 공통 생성 코드 실행new UstraRealGrid(...).build()
↓
조회 · 정렬 · 편집 · CRUD · 엑셀 · 이벤트RealGrid 계약을 유지한 채 선택된 엔진으로 동작

3. 어댑터가 하는 일

Toast 선택 시 공통 처리

  • UstraRealGrid와 UstraRealGridColumn 이름으로 화면 API 유지
  • RealGrid식 컬럼·에디터·렌더러를 Toast 옵션으로 변환
  • 행 상태, 포커스, 정렬, 병합, 저장·삭제 데이터 형식을 보정
  • Toast 이벤트를 화면이 기대하는 RealGrid 이벤트 형태로 중계

공통화하기 어려운 뷰 예외

  • 상세 조회·하위 그리드와 결합된 포커스 초기화
  • Toast의 beforeChange와 RealGrid 커밋 시점 차이
  • 조직도·팝업·셀렉트·iframe 높이 등 메뉴별 DOM 처리
  • getToastGrid() 존재 여부를 확인한 Toast 전용 분기

4. 직접 링크로 엔진 확인하기

아래와 같이 같은 메뉴에 gridEngine을 붙여 엔진을 즉시 비교할 수 있습니다.

GET 샘플
http://localhost:8081/system/standard/view?gridEngine=toast

RealGrid 비교가 필요하면 마지막 값을 realgrid로 바꿉니다. 두 엔진은 동시에 로드되지 않으며, Toast 경로에서 RealGrid 자원이 함께 발견되면 어댑터가 초기화를 중단합니다.

5. 기준 파일

application.yml — 기본 엔진 설정
layout/footerlayout.html — 공통 자원 택일 로드
layout/configlayout.html — RealGrid 라이선스 분기
layout/mainconfiglayout.html — 메인 설정 레이아웃 분기
ustra.toast.grid.js — Toast 래퍼
ustra.grid.compat.js — RealGrid 호환 어댑터
기준: 현재 저장소의 YAML 설정 및 Thymeleaf 레이아웃 로드 조건
