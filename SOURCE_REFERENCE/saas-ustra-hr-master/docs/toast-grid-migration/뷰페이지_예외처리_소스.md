# Toast Grid 뷰페이지 예외 처리 소스

## 1. 문서 목적

이 문서는 공통 Toast Grid 어댑터만으로 처리하지 못해 메뉴 뷰에서 직접 보정한 소스를 추적하기 위한 자료다.

- 기준 브랜치: `feature/toast_3차`
- 기준 커밋: `87232ca`
- 직접 수정된 뷰 파일: **45개**
- 메뉴·팝업 단위: **36개**
- 소스 기준 경로: `ustra-hr-system-thymeleaf/src/main/resources/templates/`

공통 어댑터인 `ustra.grid.compat.js`, Toast 래퍼, 공통 CSS 변경은 이 문서에서 제외한다. 뷰 파일에서 Toast 여부를 판단해 처리한 항목과 같은 마이그레이션 과정에서 확인된 화면 자체 결함만 다룬다.

## 2. 예외 처리 원칙

뷰에서는 다음 조건에 해당할 때만 별도 코드를 둔다.

1. 특정 메뉴의 저장·삭제·재조회 순서처럼 업무 흐름에 종속된 경우
2. 마스터·상세 구성이나 팝업의 숨김 Grid처럼 화면 DOM 구조에 종속된 경우
3. 공통 어댑터에서 일괄 적용하면 다른 메뉴의 동작이 바뀌는 경우
4. RealGrid와 Toast가 사용하는 행 식별 방식이 달라 화면의 대상 행을 직접 보정해야 하는 경우

Toast 실행 여부는 공통 어댑터에만 존재하는 `getToastGrid()`로 판단한다.

```javascript
const isToastGrid = typeof grid.getToastGrid === 'function';

// 인스턴스 생성 전에는 prototype으로 확인한다.
const isToastGridEngine =
    typeof UstraRealGrid.prototype.getToastGrid === 'function';
```

`getToastGrid()`가 없는 RealGrid 경로는 기존 로직을 그대로 실행한다.

## 3. 대표 예외 처리 소스

### 3.1 정렬 후 표시 첫 행으로 포커스

- 메뉴: 업무기준관리
- 파일: `system/standard.html:262`
- 원인: 정렬이 유지된 상태에서 `focus(0)`을 호출하면 표시 첫 행이 아니라 조회 순서의 `dataRow: 0`이 선택된다.
- 처리: 현재 표시 순서의 첫 `itemIndex`를 실제 `dataRow`로 변환해 포커스한다.

```javascript
var grid = standardGrid.getGrid();
var firstDataRow = (grid.getItemCount() > 0)
    ? grid.getDataRow(0)
    : 0;
standardGrid.focus(firstDataRow);
```

이 보정은 RealGrid와 Toast 양쪽에서 동일하게 확인된 화면 로직 문제이므로 엔진 분기 없이 적용한다.

### 3.2 Excel 양식 생성용 보조 Grid 숨김

- 메뉴: 교육과정 Excel 등록 외 업로드 팝업
- 파일 예시: `edu/edumng/edumngcourseupload.html:154`
- 원인: RealGrid에서는 화면에 드러나지 않던 Excel 양식 생성용 Grid가 Toast에서는 일반 Grid처럼 렌더링된다.
- 처리: Toast 실행에서만 보조 Grid 컨테이너를 숨기고 Grid 인스턴스는 그대로 생성해 Excel 양식 생성 기능을 유지한다.

```javascript
if (typeof UstraRealGrid.prototype.getToastGrid === 'function') {
    document.getElementById(_prefix + 'ExcelGrid').style.display = 'none';
}

edumngcourseuploadExcel =
    new UstraRealGrid(_prefix + 'ExcelGrid', columns, {}).build();
```

적용 파일은 교육과정, 교육결과, 부서정보, 부서연관, 급여지급정보 업로드 팝업이다.

### 3.3 저장 직후 현재 탭 명시 재조회

- 메뉴: 인사업로드
- 파일: `emp/psmstupload/emppsmstupload100.html:220`
- 원인: Toast에서는 숨김 양식 Grid의 완료 콜백에 재조회를 연결하면 실제 목록 API가 호출되지 않는 경우가 있다.
- 처리: Toast는 저장 성공 직후 현재 탭 Grid를 검색 조건과 함께 직접 조회한다. RealGrid는 기존 알림 확인 후 `Setting()`을 호출한다.

```javascript
function completePsmstuploadSave(grid, gridApiUrl, result, realGridReload) {
    var message = '총 ' + result + '건 저장되었습니다.';

    if (grid && typeof grid.getToastGrid === 'function') {
        grid.load(gridApiUrl, $('#searchTable').getData(), function() {});
        $.alert(message, '알림');
        return;
    }

    $.alert(message, '알림', realGridReload);
}
```

`emppsmstupload110.html`부터 `190.html`까지 각 탭의 저장 성공 콜백이 이 공통 화면 함수를 호출한다.

### 3.4 저장·삭제 전 선택 조건 보관

- 메뉴: 부서조회권한등록, 업무별권한등록
- 파일: `system/deptinquiry.html:168`, `system/roles/deptuser.html:443`
- 원인: 저장 알림창으로 포커스가 이동한 뒤 Toast의 현재 행이 비워지면 후속 조회에 필요한 사용자·역할 조건을 잃는다.
- 처리: 요청 시작 시 현재 사용자·역할·검색어를 보관하고 성공 또는 완료 시 해당 조건으로 목록을 직접 재조회한다.

```javascript
const isToastGrid =
    typeof roleDeptUserGrid.getToastGrid === 'function';
const focusData = isToastGrid
    ? roleDeptUserGrid.getFocusData()
    : null;

$.post(apiUrl + '/deptinquiry', param, function (result) {
    if (result && result > 0) {
        $.alert('저장 되었습니다.');
    }
    searchOrgGrid(isToastGrid ? focusData : null);
});
```

### 3.5 신규 행의 실제 rowKey 사용

- 메뉴: 사업소득자관리, 일용소득자관리, 외국법인소득자등록
- 파일 예시: `pay/paywht/pr630.html:704`
- 원인: 화면의 `id` 값은 선언 컬럼이나 조회 필드가 아니어서 Toast에서는 정상 rowKey가 되지 않는다.
- 처리: Toast는 삽입 API가 반환한 실제 rowKey로 포커스하고, RealGrid는 기존 `focus(id, 1)` 흐름을 유지한다.

```javascript
const insertedRowKey = pr630Grid.insertFocusRow({ id: id });

if (typeof pr630Grid.getToastGrid === 'function') {
    pr630Grid.focus(insertedRowKey, 1);
    $('#pr630Detail').data('state', 'update');
} else {
    pr630Grid.focus(id, 1);
}
```

상세 폼의 신규 저장 API가 `PUT` 계약을 사용하므로 Toast 경로에서 폼 상태도 `update`로 맞춘다.

### 3.6 삭제 전에 D 페이로드 생성

- 메뉴: 연차부여개수업로드, 근태내역관리
- 파일 예시: `wrk/wrkupload/wrkuploadyear100.html:231`
- 원인: Toast에서 행을 먼저 제거한 뒤 삭제 데이터를 읽으면 화면에서만 사라지고 서버 요청 데이터가 비는 경로가 있었다.
- 처리: 선택 시점의 행을 C행과 DB 저장 행으로 나누고, 저장 행은 삭제 전에 `rowStatus: 'D'` 페이로드를 만든다.

```javascript
var createdRows = checkedRows.filter(function (row) {
    return row.rowStatus === 'C';
});
var persistedRows = checkedRows.filter(function (row) {
    return row.rowStatus !== 'C';
}).map(function (row) {
    return $.extend({}, row, { rowStatus: 'D' });
});

wrkyearUploadGrid.removeRows(createdRows.map(function (row) {
    return row.rowKey;
}));

var toastParam = wrkyearUploadGrid.toDataJson(
    'wclvedayList', persistedRows
);
```

서버 삭제가 성공하면 재조회하며, C행은 서버 요청 없이 로컬에서만 제거한다.

### 3.7 마스터·상세 화면에 Toast 표지 클래스 적용

- 메뉴: 원천세 지급명세 화면
- 파일 예시: `pay/paywht/pr640.html:329`
- 원인: 지급명세 화면의 마스터·상세 flex 구조와 toolbar 폭은 공통 Grid 컨테이너만으로 조정할 수 없다.
- 처리: Toast Grid가 실제 생성된 화면에만 `is-toast-grid` 클래스를 붙여 화면 전용 CSS 범위를 제한한다.

```javascript
const toastPaymentLayout =
    document.querySelector('.paywht-payment-layout');

if (typeof earnerGrid.getToastGrid === 'function' && toastPaymentLayout) {
    toastPaymentLayout.classList.add('is-toast-grid');
    toastPaymentLayout.style.setProperty(
        'overflow-y', 'visible', 'important'
    );
}
```

사업·기타·이자배당·일용·외국법인 지급명세 화면이 같은 패턴을 사용한다. 연간이자배당 화면은 복합 헤더와 본문 높이를 화면에서 추가 지정한다.

### 3.8 화면 표시와 Excel 숫자 형식 분리

- 메뉴: 특별휴가관리
- 파일: `wrk/wrkleav/wrkleavemng100.html:316`
- 원인: 화면 값은 정수 표시를 유지해야 하지만 Excel에서는 RealGrid와 같은 최대 두 자리 소수 형식이 필요하다.
- 처리: Toast 컬럼에만 `excelFormat`을 추가한다.

```javascript
.addNumber('lveCnt', '부여개수', 'i18n', 120, false,
    Object.assign({
        required: true,
        align: 'center',
        numberFormat: '#,##0.##'
    }, typeof UstraRealGrid.prototype.getToastGrid === 'function'
        ? { excelFormat: '#,##0.0#' }
        : {}
    )
)
```

### 3.9 엔진과 무관한 화면 이벤트 결함 수정

Toast 마이그레이션 확인 과정에서 발견했지만 두 엔진에 공통으로 발생하는 화면 결함은 Toast 분기를 두지 않았다.

교육과정관리에서는 추가 버튼이 상세 폼만 비워 현재 행을 다시 클릭해도 `onCurrentRowChanged`가 발생하지 않았다. `edu/edumng/edumngcourse.html:506`에서 상세 폼과 현재 행을 함께 해제한다.

```javascript
$('#btnAdd').on('click', function () {
    clearDtl();
    edumngcourseGrid.getGrid().clearCurrent();
});
```

복리후생신청·의료비신청·학자금신청에서는 현재 행 해제 이벤트가 다시 `add()`를 호출해 추가·재선택 흐름이 꼬였다. 각 화면의 `onCurrentRowChanged`에서 `_newRow === -1`일 때 `add()`를 호출하던 분기를 제거했다.

## 5. 검토 시 확인할 항목

뷰 예외를 추가하거나 수정할 때에는 다음 사항을 확인한다.

- Toast 분기가 `getToastGrid()` 존재 여부로 한정돼 RealGrid 기존 흐름에 영향을 주지 않는가
- 공통 어댑터에서 해결할 수 있는 문제를 메뉴마다 반복 구현하지 않았는가
- 저장·삭제 전에 선택값과 페이로드를 확보해야 하는 화면인가
- 정렬된 `itemIndex`, 데이터의 `dataRow`, Toast의 `rowKey`를 혼용하지 않았는가
- 신규 C행과 DB 저장 행의 삭제 경로가 분리돼 있는가
- 팝업을 다시 열거나 재조회한 뒤에도 숨김 Grid와 이벤트가 중복되지 않는가
- 화면 전용 CSS가 `.is-toast-grid` 같은 표지 클래스 아래로 제한돼 있는가
- 실제 DB 저장·삭제, 권한, 대량 데이터, Excel까지 검증했는가

직접 수정 파일 목록은 구현 범위를 의미하며 전체 업무 시나리오의 검증 완료를 의미하지 않는다.
